# Allevia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Allevia, the company brain on FalkorDB described in
`docs/superpowers/specs/2026-10-15-allevia-design.md`, with Aamdani and AVS Atelier as its first two businesses.

**Architecture:**
- Ingestion turns sources into typed nodes and relationships in one FalkorDB graph per business. Every fact carries its
  source and time.
- A Claude Agent SDK agent (on the founder's subscription) answers only through graph tools. The server checks its
  citations and numbers.
- A Hono API streams answers and graph paths to a Vite/React app, a Discord bot and an MCP server.

**Tech Stack:**
- Node 24, TypeScript 7, tsx, vitest 5.
- falkordb 6.8 (server 6.0.2), @anthropic-ai/claude-agent-sdk 0.3.300, zod 4.
- hono 4 and @hono/node-server 2, @modelcontextprotocol/sdk 1.32, @huggingface/transformers 4.3 (e5-small).
- Playwright, discord.js 14, Vite 8, React 19, react-force-graph-2d.

**How this plan is written:**
- Each milestone produces working, tested software.
- Every task lists its files, the exact interface it must export, the tests that define "done" (real test code for
  the core behaviour), and the commands to verify.
- Implementation bodies are left to the implementer when the interface and tests pin the behaviour down. The founder
  delegated the design calls, and this keeps one source of truth: the repo.

**Rules for every task:**
- TDD: write the test, watch it fail, implement, watch it pass.
- `npm run typecheck && npm test` before every commit.
- Commit messages are `<area>: <what>` and end with the `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
  trailer.
- Never commit anything under `data/`, `models/`, or any secret.
- Integration tests use a throwaway graph `allevia_test_<random>` on `ALLEVIA_FALKORDB_URL` (default
  `redis://127.0.0.1:6390`) and delete it in `afterAll`.
- Read-only towards every external system except the private repo `Ankit-Vohra/allevia`.

### Task 1.4: Indexes and temporal upsert (`src/graph/indexes.ts`, `src/graph/upsert.ts`)
```ts
export async function ensureIndexes(g: GraphHandle): Promise<void>; // range Entity.id; fulltext Entity(name,summary), Chunk(text); vector Entity.embedding, Chunk.embedding (384, cosine). Idempotent (ignore "already indexed").
export interface NodeInput { type: EntityType; id: string; name: string; summary?: string; props?: Record<string, Prim>; src?: string; asOf?: string; simulated?: boolean; embedding?: number[] }
export interface EdgeInput { from: string; type: RelType; to: string; props?: Record<string, Prim>; since?: number; src?: string; asOf?: string; conf?: number; functional?: boolean }
export async function upsertNode(g, n: NodeInput, now?: number): Promise<{created: boolean; versioned: boolean}>;
export async function upsertEdge(g, e: EdgeInput, now?: number): Promise<{created: boolean; closed: number}>;
export async function closeEdge(g, from, type, to, now?, reason?): Promise<number>;
export async function addObservation(g, o: {subject: string; metric: string; value: number; unit?: string; windowStart?: string; windowEnd?: string; asOf: string; src: string; simulated?: boolean}): Promise<string>; // returns obs id (deterministic: obs:<metric>:<subject>:<windowEnd|asOf>)
export async function writeBatch(g, w: {nodes: NodeInput[]; edges: EdgeInput[]; observations?: ...[]}): Promise<WriteStats>;
```
Semantics (each has an integration test):
1. `upsertNode` twice with the same props: one node, `created` on the first call only, no Version.
2. A tracked prop changes: a `Version` node holding the old props, `HAD_VERSION`, Version.until = now, and the
   current props updated.
3. `upsertEdge` twice: one current edge (where `until IS NULL`).
4. A functional edge whose target changes (Task OWNS: founder → agent): the old edge gets `until` and `retiredAt` set,
   the new edge is current, and both remain in the graph.
5. `closeEdge` never deletes.
6. A missing endpoint: `upsertEdge` throws `MissingEndpoint`.
7. `isAllowed` is enforced: a disallowed pattern throws `DisallowedRelationship`.

### Task 3.1: Contracts (`src/agent/types.ts`)

### Task 3.2: Tools
Each tool family lives in `src/agent/tools/<family>.ts` and exports
`defineTools(ctx: ToolContext): AlleviaTool[]`. `AlleviaTool = {name, description, input: ZodRawShape, run(args): Promise<ToolResult>}`.
`ToolContext = {graph: GraphHandle; tenant: string; turnId: string; asker: string; touched: TouchedSet}`.

Every tool result goes through `ctx.touched.add(result)`. The tools are the ones in spec §7.2. `cypher` uses
`roQuery`, a 5 s timeout and a 200-row cap, and rejects `CALL db.idx.*.create*`-style procedures.

The integration tests seed a small graph per family and assert that `nodes`, `edges` and `sources` are filled.

### Task 3.3: Checks (`src/agent/checks.ts`)
`checkTurn(answer, touched: TouchedSet): TurnChecks`. Rules from spec §7.4. Unit tests:
- A cited id that was not touched is flagged.
- "55 signups" with 55 present in a tool result passes.
- "56 signups" fails.
- Dates (2026-10-05, 5 Oct) are ignored.
- A simulated node touched without the word "simulated" in the answer fails.

### Task 3.4: Memory (`src/agent/memory.ts`)
- `startSession(channel, asker)` and `saveTurn(...)`, which writes Turn, `TOUCHED`, `CITED`, `ASKED`, `IN_SESSION`
  and the event log JSON.
- `recallBrief(g, question, entityIds) -> {text, ids}`.

Integration test: two sessions about the same entity. The second brief contains the first turn's id.

### Task 3.5: Runtime and ask
- `AgentRuntime { run(input: {system: string; prompt: string; tools: AlleviaTool[]; resume?: string; model: string; subagents?: SubagentDef[]}, emit: (e: AgentEvent) => void): Promise<{text: string; sessionRef?: string}> }`.
- `ClaudeAgentSdkRuntime` maps SDK stream messages to AgentEvents. The settings are verified in the spike:
  `settingSources []`, `tools []`, the allow-list, `dontAsk`, and no `ANTHROPIC_API_KEY`.
- `FakeRuntime` follows a script, for tests.
- `ask({tenant, question, sessionId?, asker, channel}, emit)`:
  1. Search and build the recall brief.
  2. Build the prompt.
  3. Run.
  4. Collect `show_path`.
  5. Run the checks.
  6. Persist the Turn.
  7. Emit `final`.
- CLI `ask`. Test with FakeRuntime: the event order, the persisted Turn, and checks flagging a fabricated number.
