# App audit, 17 Oct 2026

The founder used the app on 17 Oct and wrote: "there are so many bugs, please do a detailed audit on the app, ensure
everything is 100% functional, UI is clean and understandable". This is what was checked, what was broken, what is
fixed and what is still open.

## How it was checked

- **Playwright, headless, one browser at a time**, driving the real apps at 1280 px and 375 px wide.
- **The founder's Mac** at http://127.0.0.1:8787 (sign-in off). Reads on aamdani, avs_atelier and demo_growth; asking,
  approving and the Studio on **demo_growth only**. Nothing was approved or decided on aamdani or avs_atelier.
- **The live site** at https://13-232-139-42.sslip.io (sign-in on), as a signed-out visitor with "See the demo"
  (demo_growth and bluetokai, read-only). No account was created. One question was asked there.
- **The fixed code** was checked against both: the web app built from this branch and served by `vite preview`, with its
  API calls passed to the Mac server (port 4173) or to the live server (port 4174). The two server fixes (Studio) were
  checked with server tests on the test database (127.0.0.1:6391), because the Mac server still runs the old server code.
- **Every page:** console errors, failed requests, horizontal overflow, skeletons still showing after 6 s, and a
  screenshot. **Hands-on:** asking the whole team and one person, Watch the team talk, the full work log page, opening
  stored threads (including broken ones), Approvals (Look, Change then Cancel, Approve with edits, No thanks, OK),
  Insights (open an idea), the Studio (a real photo upload on demo_growth), the Brain (search, the panel, every tab
  including What breaks, Watch it grow), Your team (a change in words, previewed, not saved), every top bar link, every
  More menu entry, the theme menu, the business switcher, Onboarding (the form, not submitted), sign-in and sign-up.

Screenshots: `docs/screenshots/audit/`. `before-*` is what the founder saw; `after-mac-*` and `after-live-*` are this
branch's web app on each server's data.

## Why the Mac and the live site looked different

The Mac server was restarted at 15:28 and its API was current, but it serves the web app from `web/dist`, and that was
built at 10:00. Restarting the server does not rebuild it, so the Mac showed the morning's screens (the old Home with
the big draft card and "Waiting for your OK") while the live site showed the new Home ("Needs your OK" rows, the brain,
the three tiles). With the same build the two Homes have the same top bar, the same sections in the same order and
nothing twice: greeting, ask box, the brain, Needs your OK, the three tiles, Set up.
(`before-mac-home-stale-build-1280.png`, `before-live-home-1280.png`, `after-mac-home-1280.png`,
`after-live-demo_growth-home-1280.png`.)

The server now warns at start when `web/dist` is older than the web source, and gives the build command. **To fix the Mac
now: `npm --prefix web run build`, then reload the page.** The server only needs a restart for the two Studio fixes.
